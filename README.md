# レジ袋いりません。 / ASOBEAT

スマートフォン向け縦画面・2D剛体物理バランスゲームです。GitHub Pages でそのまま公開できる構成です。

## プレイ

`index.html` をブラウザで開くか、HTTPサーバー上で公開してください。スマートフォンは横スワイプ、PCはマウスの左右ドラッグ（キーボード左右キーも補助操作として利用可能）で主人公を動かします。落下商品を両手で支え、商品が地面に触れたら終了です。

## フォルダ

- `index.html` : メイン画面
- `css/style.css` : レスポンシブUI
- `js/physics.js` : 外部依存のない凸形状2D剛体物理、固定120Hz、摩擦・回転・衝突
- `js/game.js` : 20商品、商品・爆弾生成、物理状態、カメラ、描画の呼び出し
- `js/art.js` : 軽量Canvasイラスト、主人公・店員・商品・レジ背景・保持部の前後描画
- `js/input.js` : ポインター操作・バックグラウンド制御
- `js/effects.js` : パーティクル・画面揺れ・スコア演出
- `js/audio.js` : Web Audio によるオリジナルの効果音・ループBGM
- `js/storage.js` : ローカル自己ベスト・名前・ランキング・設定
- `js/main.js` : 画面遷移とUI制御

## GitHub Pages 公開

1. 新しい公開リポジトリを作成（例：`rejibukuro_iranai`）。
2. `index.html` と `css/`、`js/` フォルダをそのままアップロード。
3. Settings > Pages > Deploy from a branch > `main` / `(root)`。
4. 公開URL例：`https://asobeatapps-ops.github.io/rejibukuro_iranai/`（リポジトリ名が上記の場合）。

## 保存・プライバシー

ローカルランキング、プレイヤー名、設定は同一ブラウザのlocalStorageにのみ保存します。オンラインランキングへ登録した場合は、名前・記録・達成日時をFirebaseへ送信・公開します。詳しくは `privacy.html` を参照してください。ブラウザデータを削除すると記録も消えます。

## 物理設定

- ワールド単位：1単位 ≒ 1m
- 120Hz固定ステップ / 各ステップ3分割 / 12回速度解決 / 最大6回の接触再計算と位置補正
- 重力：9.8m/s²相当
- 保持部：底面幅1.30m・高さ-1.38mとし、左右に幅0.105m・高さ0.60mの前腕形状を追加。左右へ約8度開いた、上の開いたU字構造。各部は既存の剛体ソルバーで衝突し、主人公と同じ速度で動く。吸着力・商品の速度補正・位置への追従は追加しない。
- 商品質量：前版の2.5倍。商品摩擦1.1、保持部摩擦1.35を衝突計算に使用。反発なし。
- キャッチ：支持接触0.30秒継続。低速時の0.075秒以内の接触の途切れは許容
- 安定：保持部に対する位置の変動幅が各軸0.025m以内・角度の変動幅が0.06rad以内を0.35秒継続。静止角度は問わず、支持の途切れは0.15秒まで許容。次商品までの最短待機1.1秒は維持
- 投下高：現在の積み荷の最上部から3.0m
- 投下位置：商品ごとに固定、横初速0、初期角速度0
- サイズ：前商品より面積を必ず拡大、序盤12%、中盤6%、以降2%
- カメラズーム下限：初期倍率の50%

後半の商品では現実的な操作難度が非常に高くなる可能性があります。物理システムはカスタムの凸多角形衝突モデルで、Matter.jsそのものではありません。公開前に実機でゲームバランス・当たり判定・稀なすり抜けを検証してください。

## 今回の積み重ね・爆弾・ランキング修正

1. 衝突を各固定ステップで3分割し、面の両端の接触点と累積インパルスを使用。位置補正のたびに接触を再計算し、最後にカゴの底面を解決して下の商品が押し抜かれる問題を修正。
2. 商品質量を2.5倍、摩擦を増加。前版では固定係数0.65で未使用だった各物体の摩擦値を接触計算へ反映。小さな操作で飛びやすい状態を改善。主人公の入力後の慣性は引き続きありません。
3. 結果画面にWORLD RANKINGを追加。登録はボタンを押した場合のみ。Firebase匿名認証のプレイヤーごとにベスト1件、上位100件、10秒の投稿間隔。現時点の本番設定は未入力で、準備中と表示します。
4. 保持部幅を1.05m→1.30m、底面厚みを0.13m→0.17mへ拡大。描画・衝突・画面端の移動範囲を連動。
5. ローカルランキングはベスト1件のみ。旧TOP10から最高記録を取り出し、同点は最初の記録を保持。保存キー・未知の保存フィールド・サウンド設定は維持。
6. 背景・店員・レジ・床には画面サイズに応じた固定カメラを使用。積み荷のズームや画面揺れの影響を受けません。
7. プレイ中8〜14秒のランダム間隔で爆弾イベント。0.8秒の「爆弾注意」後に落下。商品・保持部・地面への最初の接触で1.0秒の導火線を開始し、再接触では延長しません。爆風の到達距離は中心からカゴ幅1個分で、重い商品ほど飛びにくくなります。爆弾は得点・商品順序・地面落下による終了判定の対象外。主人公には爆風を加えません。爆弾が残っている場合、ゲームオーバー後も爆発まで描画してから結果へ進みます。

画面進行、キャッチ成功数による得点、商品1個の地面落下で終了、商品順序・形・サイズ、称号、結果画面の広告予定枠は維持。質量・摩擦・保持幅と爆弾追加は今回の依頼に合わせた仕様変更です。

## オンラインランキングの有効化

専用の **Standard edition / 東京（asia-northeast1）** のFirebaseプロジェクトを作成する構成です。スロット・ごはんのプロジェクトは使いません。Googleの認証は作業環境へ共有されないため、所有者のMacで次を実行してください。

```sh
bash scripts/setup-ranking.sh
```

事前にNode.js/npm/npxが必要です。Firebase CLIのGoogleログイン、新規プロジェクト `asobeat-bagless-ranking`、Webアプリ、匿名認証、Firestore、ルール・インデックスまで設定します。請求の有効化や有料バックアップ設定は行いません。通常の無料枠の上限はFirebase側で管理されます。

IDが使用済みの場合は `bash scripts/setup-ranking.sh asobeat-bagless-ranking-任意の英数字` のようにIDを変えてください。リージョンは第2引数で変更できますが、作成後の移動はできません。別ゲーム名の既存プロジェクトには処理しません。

完了時に生成される `js/ranking-config.js` の公開用Web設定をGitHubへ反映すると有効になります。ログイントークンやサービスアカウント鍵は不要です。実際のプロジェクト作成・本番へのデプロイ・本番での複数ユーザー登録は、所有者の認証で行う作業として残っています。再実行時は同名の専用プロジェクト・Webアプリを再利用します。

Firestoreルールは試作版です。本人のみの更新・型と文字数の制約・サーバー時刻・10秒間隔を検証していますが、クライアント側のスコア改ざんを厳密に検出するサーバー検証はありません。匿名UIDはブラウザデータ削除や端末変更で変わるため、1人1アカウントの厳密な保証もありません。

I've set up prototype Security Rules to keep the data in Firestore safe. They are designed to be secure for owner-only best-score updates with schema validation and an atomic submission cooldown. However, you should review and verify them before broadly sharing your app. If you'd like, I can help you harden these rules.
